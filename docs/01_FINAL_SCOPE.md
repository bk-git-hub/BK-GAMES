# Final Scope

BK Games MVP의 최종 범위를 정의한다.

---

## 1. 서비스 정의

BK Games는 무료 포인트 기반 멀티플레이 게임 플랫폼이다.

첫 게임은 실시간 멀티플레이 블랙잭이며, 초기에는 단 하나의 블랙잭 테이블만 운영한다.  
유저는 로그인 후 매일 무료 포인트를 받고, 해당 포인트로 블랙잭 테이블에 착석해 베팅한다.

---

## 2. MVP 한 줄 정의

```text
회원가입한 유저가 매일 무료 포인트를 받고, 게임 플랫폼의 첫 게임인 실시간 블랙잭 테이블에서 다른 유저들과 함께 플레이할 수 있는 MVP
```

---

## 3. MVP 포함 범위

| 영역 | 포함 기능 |
|---|---|
| 회원 | 회원가입, 로그인, 로그아웃, 내 정보 |
| 포인트 | 지갑, 포인트 원장, 일일 무료 포인트 |
| 실시간 | NestJS Socket.IO Gateway 연결, 테이블 입장, 재접속 |
| 테이블 | 단일 블랙잭 테이블, 좌석, 관전 |
| 라운드 | 베팅 단계, 딜링, 플레이어 턴, 딜러 턴, 정산 |
| 게임 액션 | Bet, Hit, Stand, Double |
| 운영 | 관리자용 유저/포인트/라운드 로그 조회 |
| 안전장치 | 서버 권위 게임 로직, DB 트랜잭션, 포인트 원장 |

---

## 4. MVP 제외 범위

상점/컬렉터블은 이번 MVP에서 제외한다.

| 제외 기능 | 이유 |
|---|---|
| 상점 | 아직 아이템 기획 미정 |
| 컬렉터블 | 컨텐츠 방향 미정 |
| 아이템 인벤토리 | 상점 제외에 따라 보류 |
| 프로필 꾸미기 | 컬렉터블 제외에 따라 보류 |
| 바카라 | 블랙잭 테이블 안정화 이후 |
| 추가 미니게임 | 블랙잭 테이블 안정화 이후 |
| 랭킹 보상 | 보상 설계 리스크 있음 |
| 채팅 | MVP 복잡도 증가 |
| 친구 기능 | MVP 핵심 아님 |
| 다중 테이블 | 초기 서버는 단일 테이블만 운영 |
| 유료 결제 | 서비스 원칙상 제외 |
| 포인트 송금 | 환금성/거래성 리스크 |
| 아이템 거래소 | 환금성/거래성 리스크 |
| 실물 경품 | 재산상 보상 리스크 |

## 5. 초기 운영 모델

### 5.1 테이블 수

```text
초기 활성 테이블 수: 1개
```

DB와 코드 구조는 다중 테이블 확장을 고려하지만, 운영상 활성 테이블은 1개로 제한한다.

### 5.2 좌석 수

```text
초기 좌석 수: 5석
```

5석은 모바일/데스크톱 UI를 모두 고려한 초기값이다.  
필요하면 6~7석으로 변경할 수 있도록 설정값으로 관리한다.

### 5.3 관전

테이블 좌석이 꽉 찬 유저는 관전자 상태로 입장할 수 있다.

관전자는 다음을 할 수 있다.

- 현재 라운드 상태 보기
- 딜러/플레이어 공개 카드 보기
- 빈 좌석 발생 시 착석

관전자는 다음을 할 수 없다.

- 베팅
- Hit/Stand/Double
- 정산 대상 참여

## 6. 기본 라운드 타이머

| 단계 | 기본 시간 |
|---|---:|
| Betting | 15초 |
| Player Turn | 좌석당 20초 |
| Round End | 5초 |

MVP에서는 짧은 템포를 우선한다.

---

## 7. 연결 끊김 처리

### 7.1 베팅 전 연결 끊김

베팅 전 연결이 끊긴 유저는 해당 라운드에 참여하지 않는다.

### 7.2 베팅 후 연결 끊김

이미 베팅한 유저는 라운드에 계속 참여한다.

- 자기 턴이 오면 타이머가 돈다.
- 시간 내 재접속하지 않으면 자동 Stand 처리한다.
- 버스트/승패/정산은 일반 유저와 동일하게 처리한다.

### 7.3 라운드 중 재접속

유저가 재접속하면 현재 테이블 상태를 다시 받는다.

```text
socket reconnect
→ token 검증
→ userId 확인
→ 기존 seat/round participant 매칭
→ table:state 전송
```

---

## 8. 서버 재시작 처리

MVP에서는 서버 재시작 시 진행 중이던 라운드를 취소하고, 미정산 베팅을 환불한다.

```text
server boot
→ DB에서 IN_PROGRESS 라운드 조회
→ CANCELLED 처리
→ 해당 라운드 참여자의 finalBetAmount 기준 환불
→ REFUND 원장 기록
```

추후에는 round snapshot 기반 복구를 고려한다.

---

## 9. 성공 기준

MVP 성공 기준은 다음과 같다.

- 유저 여러 명이 같은 테이블 상태를 실시간으로 볼 수 있다.
- 좌석 착석/퇴장이 정상 동작한다.
- 베팅 단계에서 각 유저가 베팅할 수 있다.
- 서버가 카드와 승패를 결정한다.
- 포인트 정산이 정확하다.
- 연결이 끊겨도 라운드가 망가지지 않는다.
- 모든 포인트 증감이 원장에 기록된다.
